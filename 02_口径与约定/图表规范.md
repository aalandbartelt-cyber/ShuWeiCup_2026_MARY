# 数维杯 2026 图表规范

本规范依据现行数模 skill 的 `references/05_高视觉质量图表.md`、`assets/visual_style_guide.md`，并落实用户 2026-11-20 的明确要求。用户要求作为本项目的执行标准。共享配置为 `configs/figure_style.json`，Python 实现为 `src/shuwei_c/figure_style.py`。

全文结构、公式、求解器、引用、附录及反馈整改清单，另见[论文写作与审稿规范](论文写作与审稿规范.md)。其中“当前必须保持的状态”记录摘要、第 7/8 节留空及附录 A 延后约定，后续问题必须继承。

1. **所有图内文字统一 Times New Roman**，包括坐标轴、刻度、图例、数字标注及子图编号；数学符号使用同字体可用字形。禁止静默回退到 DejaVu Sans、Arial、Liberation Serif 等字体。导出后检查 PDF 字体实际嵌入。
2. **图题、总标题、解释性图注不得出现在图片内部。** 不使用 `plt.title`、`ax.set_title`、`suptitle`；图题和 caption 在论文中独立排版。图内保留坐标轴及单位、图例、必要数据标注和 A/B/C 子图编号。图题简短，子图分别表示什么由相邻正文说明。
3. 按最终论文版心设计图件，不再以 7 英寸原尺寸直接插入。当前 160 mm 版心中，多面板图居中使用约 88% 版宽（140.8 mm），简单图约 82%（131.2 mm），依据内容再调整；不得超版心或顶满左右边界。最终印刷尺寸的基础文字不低于 8 pt；若缩放使字体过小，重排图件而非硬缩。数学上下标按正常比例。
4. 配色遵循 skill 的**语义明确、跨图一致、主次分明、灰度可辨**原则。skill 并未规定唯一官方 HEX 色板；本项目采用以下固定语义映射，不把它称作官方强制色值。

| 颜色 | HEX | 默认用途 |
| --- | --- | --- |
| 灰 | `#9A9A9A` | 常数/频率等简单基线 |
| 蓝 | `#466C9B` | 数值基线/数值增强；训练集 |
| 绿 | `#228B77` | 当前主要候选或选定方法 |
| 橙 | `#D88C32` | 质量调整、低质量区域；验证集 |
| 灰紫 | `#B85C7B` | 视频增强或相关概率曲线 |
| 深灰 | `#25333A` | 文字 |
| 浅灰 | `#E2E7E9` | 辅助网格 |

不同任务中的类别以图例明确含义；同一组图内相同对象不得任意换色。直接比较增加线型、点形或直接标注，不能只靠红绿区分。连续热图必须使用与图元一致的色标与归一化，缺失值单独说明。

5. 比较同一物理量时使用兼容量程；不同量程必须明确说明，不用未说明的双轴、截断或缩放制造差异。零值不得在对数图中静默改成小正数。
6. 保留 PDF 矢量图、可编辑 SVG 与 600 DPI PNG。SVG 在其他设备需安装 Times New Roman；PDF 嵌入字体作为便携版。原始字体文件不随项目或支撑包分发。
7. 每张图必须记录问题/主张、源 CSV、条件和单位、独立样本量、不确定性口径、外部英文 caption、生成脚本及哈希。以源数字复算图表，不用漂亮外观替代正确性。
8. 导出时自动拒绝非空图内标题、错误字体、过小字体；导出后人工查看裁切、遮挡、图例、共享量程与最终尺寸。用户审图前的图为候选图，不冒称已获用户审阅。

## 图例必须阐明（2026-11-20 用户补充）

9. **每种承载信息的颜色、线型、点形、填充、误差棒、阴影带和参考线，都必须在图例、明确的直接标签或相邻正文中对应到具体含义。** 图内能简洁解释的优先图内图例；不能让读者猜灰色虚线、竖线或点的含义。仅有 A/B 字母不解释分组或统计编码。
10. 方法名使用可理解的全称或“全称（缩写）”；不单独使用 KF、raw、model1、Q1 radius 等未解释简称。区分输入信息（数值/头部视频/腕部视频）、预测方法、校准方法与评价条件，不把它们混成无法辨认的系列。
11. 图例明确统计量：点是均值、中位数还是系数；线是连接点、拟合曲线还是阈值；区间是参数置信区间还是未来预测区间，并写清名义水平及重采样/校准口径。图例与相邻正文分工，详细统计说明放正文，避免把整个说明段塞进图片或短图题。
12. 多面板图共用图例时说明作用范围；仅对部分面板适用的图例放在对应面板附近。颜色、线型、点形联合编码时，优先列出实际存在的完整组合或直接标注，不要求读者自行把两个抽象图例拼接；阈值点直接对应实际数值。
13. 图例不得盖住重要曲线、点、柱顶或区间，不得裁切；同一对象跨图保持一致名称和编码。轴标签已逐项明确识别的单色分类条形图不强加重复图例，但所有辅助线仍须解释。
14. 每图保存 `legend_contract`：图元/编码 → 显示标签 → 精确定义 → 涉及面板 → 来源列/参数。导出检查标签实际出现，最终尺寸进行视觉核验。检查图例清晰是独立验收项，不能只验证字体和有无标题。

## 局部放大、直接数值与图例一致（用户再次补充）

15. **严重重叠、使关键差异难以辨认的折线图必须增加局部放大视图。** 主图保留全范围；明确画出放大选区框、指向放大窗的连接线和放大窗坐标刻度。主图与放大图使用相同源值、颜色、线型和点形；不得移动真实横坐标、人工增大差值或用平滑制造分离。选区应包含比较的全部方法，不只挑有利片段。相邻正文写清放大范围及理由，图题保持简短；真实重合的系列用数值/引线说明，不能伪造差异。
16. **柱形/条形图的关键数值直接标在对应柱顶、条端或条内；树状图的关键数值直接标在对应节点/分支。** 森林式区间图在对应行列出点估计与所示区间，不让读者只靠坐标估读。数字来自未舍入的同版结果，统一精度和单位，保留正负号；必要时用明确的轴倍率缩短数字。标签不得挤压、越界或遮挡其他图元。次要信息无需机械塞满图面。
17. **图例样例必须与实际图元一致：颜色、线型、点形、实心/空心、填充和条纹逐项对应。** 不用黑白的“方法样例”代替实际彩色系列，再要求读者猜组合。可把“数据集 × 方法”列成完整彩色组合；类别过多时用直接标签或分面。真实的灰色阈值线、黑色文本或无颜色含义的参考符号仍按实际样式展示。
18. 最终视觉验收增加三项：重叠关系是否能由放大窗读出；关键数字是否可直接读出并与源值相符；任意一个图例能否直接定位到实际系列。此前仅通过字体/标题/文字存在检查的图，不能据此判定已满足上述三项。

v2 原冻结图和哈希保留；图例修订版另存 `artifacts/c_q1_v3/figures_legend_revision/`，避免把绘图修订误当重新实验或覆盖原证据。

现有第一问图按本规范重新生成；后续 Q2/Q3 复用同一配置。论文正文的 12 pt Times New Roman 要求与图内字号分开管理，不将两者混为一谈。

## 论文排版补充（2026-11-20 用户反馈）

19. 图题只给简明名称，复杂面板、数据范围和统计口径移入相邻正文；不把完整解释段塞入 caption。表题同理，单位必须留在表头或正文说明。
20. 在编译后的 PDF 检查图文混排，不用强制分页把每张图单独占一页；必要的多面板大图保留可读性。
21. 普通正文统一首行缩进；紧接公式的符号解释（where / Here）顶格。公式居中、编号右对齐、多行按等号对齐，数学标点随语法。
22. 全文目录按三问结构组织；大小标题层次统一。摘要、关键词按用户要求暂空，三问完成后统一撰写。文献按首次引用顺序编号，正文方括号引用，条目格式一致、出处可追溯。

23. 论文与图表不得出现内部迭代标签；比较项使用可解释的方法名。源程序目录、哈希与内部阶段标识只留外部索引。
24. 正文按问题、模型、求解、验证的逻辑说明，减少重复声明和长串术语；命题与证明单独标示，并保留规范证毕方框。
25. 求解实现须核对实际代码和日志，说明 Python 库、具体算法/求解器、主要设置及所用 GPU 型号，区分 CPU 与 GPU 步骤，不以笼统的“Python 求解”代替。
26. 附录参照自写终稿采用简短支撑材料表及补充图表；内部构建、审阅、哈希等过程性说明放随稿文件，不将 Draft provenance 等工作记录放进论文。按用户最新要求，附录 A 当前暂不整理，最后统一处理；补充图表在附录 B 维护。

27. 多面板图若造成正文大块留白，应优先拆分为“正文核心面板＋附录诊断面板”，保持可读字号；同步改面板字母、图号与正文引用。浮动体页按顶部对齐，并避免不必要的 FloatBarrier 阻止正文填补空白。
