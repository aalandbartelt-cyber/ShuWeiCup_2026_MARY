总量是容器/元数据审计；不表示用测试轨迹拟合模型。训练、验证、测试环境分别 16、4、4，环境和场景交集均为零；训练/测试操作者重叠 3 名。内部 episode UUID 与官方 split 对齐，CSV 文件夹 UUID 不一定等于内部 episode UUID，解析器按元数据映射。没有重复 episode，源片段与元数据映射无不一致。

EgoDemo 数值来自 parquet：双手各 21×3 位置、21×4 四元数，头和头部相机位姿；质量来自独立 JSON。Demo 的关节表明确索引 0 为 wrist。Pro/Standard 来自 CSV，双手各 21×3/21×4，时间使用 `_offset_from_first_log_s`；原始纳秒整数若需要差分，先作整数相减。Pro/Standard 的数字索引未见完整解剖名称证据，因此共同状态采用几何中心。

CSV 质量表有 `is_bad` 和可变个数的 `problem_type[k]`。一条全好样例可能根本没有 reason 列；不能写死列数。理由能分左右手时分别标记，无法分配的 bad 标记保守处理为两手低质量。无标记仅表示原始提供方未标坏，不是物理准确性的证书。

开发阶段读取 62 条轨迹、53,829 帧，未发现非有限手坐标、非递增时间或 >1.5×中位时间步的缺口。质量与双手时间在开发记录中逐点对齐；详细头部时间和四元数范数检查在 `record_audit.csv`，不能据一致性声称坐标物理含义全部确认。位置单位及跨容器姿态约定仍未独立证实。
